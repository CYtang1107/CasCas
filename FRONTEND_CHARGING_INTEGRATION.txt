# CasSama: charging and recorded-revenue frontend integration

This patch connects the existing screens to the backend in GreenGru proposal Sections 1.4.1–1.4.3 and 6.2.

## Driver
- **Residential booking on shared server:** Open Activity; click **Find / refresh available bays**; select a connected bay; click **Check in** during the actual booking window. The check-in returns a one-time OCPP `idTag` which is displayed for use at that particular charger. The UI does not start the charger.
- **After check-in:** Status is read from `POST /api/bookings/:id/charging-status` every 5 seconds, with a manual refresh. `awaiting_charge` does not claim to be charging. A matching OCPP `StartTransaction` changes to `charging`. `completed` displays metered energy and calculated receipt; `needs_review` shows a warning and *no booked revenue*.
- **Demo/public chargers:** Existing simulated timer remains, but labels say “Simulated charging.” These sessions are never recorded as real OCPP activity.
- **Important:** The bundled OCPP simulator sends its own `CASSAMA` tag, not the booking-specific tag. For an end-to-end booking-linked demo use a compatible test charger as shown in `test/charging-lifecycle.test.js`.
- **Important:** Check-in uses server time; changing the on-screen demo clock does not bypass the booking window. Restarting the page loses the in-memory charging tag and current UI state. The session remains on the backend and is not billed until its valid OCPP completion.

## JMB
- The main overview is now clearly **Forecast** and remains scenario-based.
- **Recorded charging activity** is a separate PIN-authenticated, month-filtered section, using `GET /api/jmb/:condoId/charging-revenue?month=YYYY-MM`.
- kWh and calculated receipts come from completed booking-linked meter readings. Electricity/variable/fixed costs and the JMB/CPO split are illustrative estimates, not actual paid amounts.

## Run
```
npm ci
npm test
npm start
```
Open `/` for drivers and `/jmb.html` for JMB. A booking without a working OCPP bay will not show charging progress; this is accurate, not a frontend failure.
